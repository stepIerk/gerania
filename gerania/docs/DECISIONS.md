# Решения

## 2026-11-11 — расположение пакета
Пакет лежит в `gerania/Packages/GeraniaKit`, потому что `project.xcproj` уже содержит
`LIBRARY_SEARCH_PATHS`, указывающий туда. Xcode-проект — `gerania.xcodeproj` в родительской папке,
схема называется `gerania` (в нижнем регистре, как таргет).

## 2026-11-11 — scratch-path вне синхронизируемой папки
`Gerania/` — синхронизируемая папка app-таргета, поэтому SwiftPM-артефакты внутри неё
попадают в сборку Xcode (ошибка `Multiple commands produce ... ActorIsolated.h`).
Скрипты собирают пакет с `--scratch-path build/swiftpm`; не запускайте `swift build`
в папке пакета без этого флага.

## 2026-11-11 — DEVELOPER_DIR в скриптах
`swift build` через CommandLineTools не находит макрос `Preview` из KeyboardShortcuts 2.4.0.
Скрипты выставляют `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`, если он есть.

## 2026-11-11 — зависимости
textual `0.5.0` — актуальный тег, преемник MarkdownUI; KeyboardShortcuts `2.4.0` — последний 2.x.
Fallback на MarkdownUI не нужен, пока API Textual покрывает стриминговый markdown.

## 2026-11-11 — точка входа приложения
`@main` остаётся тонким и живёт в app-таргете. Общее состояние — `GeraniaAppRoot.shared.model`,
чтобы не создавать `AppModel` в `@State` внутри `App` и не дублировать его между сценами.

## 2026-11-11 — настройки
`GeraSettings` — `@Observable @MainActor` класс с явными `didSet` в `UserDefaults`.
`launchAtLogin` — только зеркало; источник истины — `SMAppService.mainApp.status`.

## 2026-11-11 — gateway ensure, а не attach
Установленный Hermes 0.23 не имеет `hermes gateway attach`; документированный и проверенный
путь — `hermes gateway ensure --json --timeout N` + минт одноразового тикета через
`<profile_id>/gateway.sock`. Тикет минчится заново на каждый reconnect.

## 2026-11-11 — approval как событие
В canonical gateway approval/clarify приходят событиями `approval.request`/`clarify.request`,
а ответ отправляется методами `approval.respond`/`clarify.respond`. JSON-RPC server request
`approval`/`clarify` поддержан как legacy-путь.

## 2026-11-11 — JSONValue и JSONRPCConnection
Свой `JSONValue` вместо `[String: Any]`: даёт Sendable, точные Int id и простые фикстуры.
`JSONRPCConnection` — актор с continuation по id, таймаутами и fail-all; транспорты только
подключают его к WebSocket/stdin и обрабатывают уведомления.

## 2026-11-11 — процесс one-shot
`ChildProcess` использует `posix_spawn` с `POSIX_SPAWN_SETPGROUP`, чтобы отмена убивала
всю группу (`kill(-pid, SIGTERM)` → `SIGKILL` через 3 с). `Process` не даёт выставить pgid
до exec.

## 2026-11-11 — префиксы промптов
`HermesConfig.prompt(for:mode:)` добавляет `voicePromptPrefix`/`textPromptPrefix` внутри
транспорта, поэтому CLI и будущий UI получают одинаковое поведение.

## 2026-11-11 — HUD-панель как non-activating NSPanel
`FloatingPanel` — borderless + `.nonactivatingPanel` + `.fullSizeContentView`, level `.statusBar`,
`canJoinAllSpaces` + `fullScreenAuxiliary`. Показ только через `orderFrontRegardless()`:
приложение никогда не активируется и не забирает key window, поэтому фокус в приложении
пользователя сохраняется. Мини-окно ввода — единственная панель с `acceptsKey = true`.

## 2026-11-11 — геометрия панелей в чистой функции
`PanelPlacement` не знает про `NSPanel`: на вход `ScreenGeometry` (frame, visibleFrame,
safeAreaInsets, auxiliaryTopLeft/RightArea) и размер панели, на выход — точка левого верхнего угла.
Так правила «у выреза / справа сверху / под иконкой меню-бара» покрываются тестами без дисплея.
Вырез определяется по двум auxiliary-областям меню-бара, экран — по позиции курсора.

## 2026-11-11 — размер окна задаёт контроллер
`PanelHost` ставит `sizingOptions = []`: иначе `NSHostingView` сжимает окно до нулевой ширины.
SwiftUI только измеряет контент (`onGeometryChange`) и сообщает высоту контроллеру.
Рост — с якорем по верхнему краю (панель растёт вниз), троттлинг 20 кадров/с,
анимация только при разнице больше 12 pt (0.22 c, easeOut).

## 2026-11-11 — Liquid Glass с запасным материалом
`GlassCard` на macOS 26 использует `glassEffect(.regular, in:)` (сигнатура проверена в SDK 27.2),
на старых системах — `.ultraThinMaterial`. Обводка 0.5 pt: white 15 % в тёмной теме,
black 10 % в светлой.

## 2026-11-11 — поток текста: буфер, санитайзер, блоки
Ответ приходит дельтами, поэтому текст копится в `StreamBuffer`: снимок публикуется не чаще
30 раз в секунду (часы абстрагированы через `StreamClock`, троттлинг проверяется тестом).
`MarkdownStreamSanitizer` закрывает незакрытую разметку в конце текста и убирает недописанную
строку таблицы, но не трогает законченную часть. Документ режется на блоки
(`MarkdownBlockSplitter`): готовые блоки рендерятся один раз, заново строится только хвост.

## 2026-11-11 — высота панели измеряется содержимым
`ScrollView` внутри окна не сообщает свою идеальную высоту, поэтому размер панели считает
не карточка, а содержимое: шапка и тело докладывают свою высоту через `onGeometryChange`,
контроллер складывает их с отступами и ограничивает `maxPanelHeightFraction`. Когда высота
упирается в потолок, `ScrollView` начинает прокручиваться.

## 2026-11-11 — markdown рендерит Textual
Рендер отдан Textual (`StructuredText`), но со своими стилями: компактные заголовки, тонкая
сетка таблиц, блок кода с фоном и кнопкой «Копировать» (`CodeBlockStyle` + `CodeBlockProxy`),
цитата с тонкой линией. Готовый блок — отдельный `StructuredText`, поэтому он парсится один раз.

## 2026-11-11 — HUD не вмешивается в фокус приложения
Показ HUD — только `orderFrontRegardless()`; key window панель забирает исключительно в состоянии
`awaitingApproval`, где нужен ⏎ и Esc. Озвучка и открытие Hermes Desktop пока без побочных
эффектов: Hermes не публикует URL-схему, сессию передать нельзя.

## 2026-11-11 — мини-окно: логика в ViewModel, а не во вью
Разбор клавиш вынесен в `InputKeyParser` (GeraniaCore), состояние — в `InputViewModel` (GeraniaUI):
и то, и другое покрыто тестами без окна. SwiftUI только переводит `KeyPress` в `InputKey`.

## 2026-11-11 — кроссфейд вместо общего перехода
HUD и мини-окно — два разных NSPanel, общий SwiftUI-переход между ними невозможен. Поэтому
отправка выглядит так: мини-окно гаснет (alpha 0, 0.16 с), HUD проявляется (alpha 1, 0.16 с),
а позиция мини-окна учитывает HUD, чтобы окна не накладывались.

## 2026-11-11 — фокус возвращается вручную
Non-activating панель не возвращает фокус приложению, которое было активно до вызова. Поэтому
при показе запоминается `NSWorkspace.shared.frontmostApplication`, а после закрытия окна оно
активируется через `activateIgnoringOtherApps` — только если система не вернула фокус сама.

## 2026-11-11 — открытие в Hermes Desktop через deep link
Deep link `hermes://open/session/<id>` — единственный способ, который Hermes Desktop
поддерживает официально: схему регистрирует сам Desktop при запуске. Проверено на живой
установке — доставка есть и при холодном старте, и при уже запущенном приложении.
Остальные способы (активация запущенного Desktop, ID в буфере обмена, синтез ⌘K/⌘V/⏎)
оставлены запасными и выбираются по возможностям машины.

## 2026-11-11 — переименование только через протокол
`session.mutate` с `operation: "rename"` — официальный метод gateway. CLI-команда
`hermes sessions rename` меняет состояние пользователя, поэтому в автоматических проверках
не вызывается, а пункт интерфейса показывается только если транспорт умеет переименование.

## 2026-11-16 — титул новой сессии из запроса
`session.create` принимает `title`, поэтому новая сессия получает первые слова запроса
(до шести слов). Заголовок показывается в списке чатов и в чипе мини-окна.

## 2026-11-11 — «уши» отдельно от приложения
`gera_ears.py` — копия логики эталона, но без Hermes, озвучки, звуков и оверлея: скрипт только
слушает, распознаёт и решает (wake/stop/команда). Приложение получает NDJSON-события и само
отвечает за состояние. Логика эталона при этом не меняется — пороги, фильтры и списки перенесены
один в один, а `tools/legacy/wake_agent.py` остаётся эталоном.

## 2026-11-11 — решения остаются в Python
Wake, стоп-слово и ожидание команды решает скрипт: он знает про спектральный фильтр и про
«Гера» в начале фразы. Приложение получает уже готовые намерения (`wake`, `command`, `stop`),
поэтому состояние UI не зависит от того, как устроено распознавание. Состояние работы и озвучки
приходит в скрипт командой `state`, а `mute` не даёт приложению услышать собственные звуки.

## 2026-11-21 — озвучка идёт по предложениям
Ответ не ждёт конца: `SentenceChunker` режет поток на предложения (минимум 24 символа,
сокращения и числа не режутся, код и таблицы пропускаются), `Speaker` ставит их в очередь
`AVSpeechSynthesizer`. Первое предложение звучит, пока Hermes ещё пишет остальные.

## 2026-11-12 — перебор моделей в самом приложении
Hermes умеет fallback-цепочку в своей конфигурации, но её настраивают вручную в терминале.
Gerania держит свой список моделей: при ошибке «лимит исчерпан» (`permission_denied`, `quota`,
`429`, `resource_exhausted`, `billing`…) следующий запрос уходит на следующую модель, а сессия
пересоздаётся (модель закрепляется за сессией при создании). Список моделей берётся из
`~/.hermes/provider_models_cache.json` — это тот же кеш, которым пользуется пикер Hermes, но
файл читается только на чтение.

## 2026-11-12 — у панелей нет тени
Панель — это отдельное окно без рамки: тень SwiftUI обрезалась его границами и оставляла
видимый контур. У карточки остался только тонкий волосяной контур и материал (Liquid Glass на
macOS 26, regularMaterial раньше). Окно отделено от фона самим материалом, а не тенью.

## 2026-11-12 — HUD продолжает чёлку, а не висит карточкой
`NotchShape` с вогнутыми «ушами» и прижатие к верхней кромке делают HUD визуальным
продолжением аппаратного выреза. Поэтому фон строго чёрный и непрозрачный, без стекла и
тени: полупрозрачная карточка в этой позиции читается как отдельная панель и спорит с
чёлкой. На внешних дисплеях без выреза сохраняется отступ под menu bar.

## 2026-11-12 — крестик означает «закрыть и остановить»
Раньше `.dismissed` прятал панель только в `done`/`error`, поэтому в «Думаю» и «Слушаю»
крестик выглядел сломанным. Теперь закрытие всегда уводит автомат в `idle` и посылает
`stopListening`/`cancelTranscription`/`stopSpeaking`/`interrupt`: невидимый продолжающийся
ход или речь хуже, чем явная остановка. Окно ответа закрывается вместе с HUD.

## 2026-11-12 — окно ответа отдельное и у правого края
HUD показывает только начало ответа; полный текст, инструменты и рассуждения — в отдельном
окне, чтобы не раздувать облачко под чёлкой. Ширина 480 pt и отступ 0 (вплотную к правому
краю) — значения по умолчанию; оба параметра вынесены в настройки. Окно не активирует
приложение при показе, но принимает клавиатуру после клика — иначе нельзя листать и копировать.

## 2026-11-12 — рамка размышления без верхней кромки
Панель прижата к верхнему краю экрана, и штрих по верхней кромке обрезается. `NotchBorder`
рисует тот же контур, но без верхнего отрезка: анимация `AngularGradient` остаётся прежней,
а к ней добавлен слабый постоянный фиолетовый контур, чтобы рамка читалась и в тот момент,
когда яркая дуга находится на другой стороне.

## 2026-11-12 — wake с допуском помех
Wake-слово ищем как подстроку без правой границы: Whisper склеивает его со следующим
словом («ГераОткрой») и добавляет точку («Гера.»). Слева граница слова обязательна, иначе
«генерал» и «superGera» будят Геру. Отдельно мягкий шаблон разрешает прилипший слог
(«НуГера») — но только для кириллицы, латинский «gera» внутри слова не подходит.

## 2026-11-12 — реплика распознаётся на ходу
Ждать конца фразы — это 0.8 с тишины плюс полная транскрипция: Гера отвечает на две
секунды позже, чем могла бы. Поэтому реплика пересчитывается частично: wake срабатывает
сразу после «Гера», команда уходит на первой паузе (0.45 с тишины) с пометкой
`via: "partial"`. Финальный разбор реплики остаётся — он точнее, и если пользователь
договорил, приложение получает уточнение и перезапускает запрос.

## 2026-11-12 — окружение голоса вне папки приложения
App-таргет — синхронизируемая папка: Xcode копирует её в Resources плоско. Любой файл
с именем, уже встречающимся в Resources (`.gitignore`, `__init__.py`, `*.pyc`), ломает
сборку «Multiple commands produce». Поэтому venv с mlx-whisper ставится в
`~/Library/Application Support/Gerania/voice-venv`, кэш pytest отключён, а байт-код не пишется.

## 2026-11-12 — две модели Whisper
Большая `whisper-large-v3-turbo` даёт точный финальный текст, но на куске реплики
думает 0.6–1.3 с — за это время цикл VAD не успевает обрабатывать микрофон, и реплика
заканчивается с опозданием. Маленькая `whisper-base-mlx` делает тот же кусок за 0.05 с:
она ловит wake-слово и растущий текст команды, пока пользователь говорит, а финальный
разбор реплики по-прежнему делает большая модель. Если маленькая модель не скачалась,
скрипт молча переходит на большую.

## 2026-11-12 — распознавание на ходу в отдельном потоке
Частичное распознавание не должно блокировать цикл VAD: пока Whisper думает, микрофон
продолжает писать кадры в очередь, и реплика заканчивается вовремя. Пока поток занят,
новые куски пропускаются — очередь не растёт.

## 2026-12 — команда уходит на паузе
Пользователь замолчал — ждать конца реплики (ещё 0.35 с тишины) и полной транскрипции
незачем: команда уходит сразу, с пометкой `via: "partial"`. Если пользователь договорил,
финальный текст приходит уточнением — приложение прерывает текущий запрос и начинает
новый. Команда не дублируется: отправка сравнивается с уже отправленной.

## 2026-11-13 — приложение обычное, а не фоновое
Раньше Геря жила только в меню-баре: `setActivationPolicy(.accessory)` убирала иконку
из Dock, а сцена `Settings` открывала отдельное окно настроек. Теперь политика
`.regular`: у приложения есть иконка в Dock, меню приложения и ⌘Q, а окно приложения
(приветствие + настройки) открывается при запуске, по клику на иконку в Dock и из
меню-бара («Окно Гера…», ⌘,). Плавающие панели остались non-activating — фокус чужого
приложения они не забирают.

## 2026-11-13 — запуск по кнопке, а не при старте
Голос поднимается только после «Запустить Геранию» в окне приложения: так macOS
спрашивает доступ к микрофону в ответ на действие человека, а не молча при запуске.
При автозапуске при входе (родительский процесс — launchd) голос, наоборот, поднимается
тихо, а окно не показывается. Отдельный маршрут `gerania://start` запускает Герю
из командной строки и из Shortcuts.

## 2026-11-13 — иконка собирается скриптом, а не в Xcode
`project.xcproj` править нельзя, а `ASSETCATALOG_COMPILER_APPICON_NAME` живёт именно
там. Поэтому иконка собирается скриптом `scripts/make_icon.sh`: мастер 1024×1024
(`tools/icon/make_icon.swift`: цветок на тёмном сквирле), десять размеров в
`AppIcon.appiconset` и `GeraIcon.icns`, который копируется в синхронизируемую папку
`gerania/` и попадает в `Contents/Resources` бандла; в `Info.plist` добавлен
`CFBundleIconFile = GeraIcon`. Имя `GeraIcon` (а не `AppIcon`) выбрано специально:
actool назовёт свою иконку `AppIcon.icns`, и одинаковые имена дали бы
duplicate output file. Назначить каталог иконкой в Xcode остаётся одним кликом
(`docs/HUMAN_TODO.md`).

## 2026-11-13 — GIF разбираем сами, а не отдаём NSImageView
`NSImageView` умеет проигрывать GIF сам, но не даёт понять, когда анимация закончилась:
приложение не знает, можно ли уже показывать настройки. Поэтому GIF разбирается через
ImageIO (кадры и паузы каждого), а кадры показываются по своему таймеру — анимация
проигрывается ровно один раз и полностью.

## 2026-11-13 — анимация живёт в окне, а не на весь экран
Первый вариант был отдельным полноэкранным окном, но это выглядит как чёрный экран
поверх всего и мешает. Теперь анимация — чёрный слой внутри окна приложения: окно
открывается чёрным, цветок раскрывается, чёрный слой тает и под ним сразу видны
приветствие и настройки. Окно одно, переход плавный, ничего лишнего не перекрывается.

## 2026-11-13 — во время загрузки окно без шапки
Серая полоса шапки над чёрным содержимым выглядела как чужой элемент. Пока идёт
анимация, шапка окна делается прозрачной и чёрной, системные кнопки прячутся, а вкладки
настроек не создаются вовсе (в macOS они живут в шапке). После анимации всё
возвращается: кнопки, вкладки и заголовок. Переключать `styleMask` не стали: это
пересчитывает геометрию окна и окно прыгает — достаточно скрыть кнопки и сделать шапку
чёрной.

## 2026-11-14 — живой диалог на Gemini 3.8 Live (R1–R8)
- R1: диалог ведёт Gemini 3.8 Live через абстракцию `LiveTransport`; провайдер
  меняется без переделки UI. Выбран `gemini-3.8-live`: русский, barge-in,
  function calling, ~$3/1M аудио-входа против $1.70–2.00 у OpenAI Realtime.
- R2: wake-word остаётся за Whisper/Python. После wake Python получает `suspend`,
  закрывает микрофон, Swift поднимает Gemini Live и владеет микрофоном; на выходе —
  `resume`. Это осознанное исключение из правила «решения принимает Python»:
  Gemini сам транскрибирует речь, а стоп-слова ловит детерминированный
  `LiveStopMatcher` по `inputTranscription`.
- R3: каждая команда — отдельная задача Hermes; одновременно до трёх, остальные
  в очереди. Уточнение идёт в ту же задачу через `steer_task`; отмена — `cancel_task`.
- R4: если задача завершилась, пока диалог открыт, Gemini получает системную заметку
  и озвучивает результат; если диалог закрыт — системный `Speaker` + уведомление.
- R5: сессия закрывается после 60 с тишины (настраивается) и принудительно через
  30 минут; включены context compression и session resumption.
- R6: ключ Gemini хранится в Keychain (`Gerania.GeminiLive`); `GEMINI_API_KEY`
  читается только как fallback для `live-probe` и CLI.
- R7: живой режим выключен по умолчанию; классический пайплайн остаётся рабочим
  и не меняет поведение, пока тумблер не включён.
- R8: wake в live не нужен (диалог непрерывный), стоп — по фразе целиком;
  «нет», «ничего», «надо» и «не» сами по себе не останавливают диалог.

## 2026-11-14 — инструменты live объявлены NON_BLOCKING
Gemini 3.8 Live по умолчанию выполняет функции асинхронно. Мы явно ставим
`behavior: NON_BLOCKING` и отвечаем `scheduling: WHEN_IDLE`, чтобы модель не
перебивала текущую речь и озвучивала результат в естественную паузу. Для
`gemini-3.8-live-extended-thinking` поле scheduling не отправляется: эта модель
не поддерживает явное планирование и закрывает сессию при нём.

## 2026-11-14 — AEC с fallback в полудуплекс
В live Swift владеет и входом, и выходом звука. Включаем voice processing у
`AVAudioEngine.inputNode`; если система не даёт, автоматически переходим в
полудуплекс (глушим микрофон, пока играет ответ). Barge-in работает только в
режиме эхоподавления — это честный компромисс вместо эха собственного голоса.

## 2026-11-14 — RealtimeKit без новых зависимостей
Транспорт — `URLSessionWebSocketTask`, аудио — AVAudioEngine, ключ — Security.
Никаких внешних SDK: пакет остаётся Foundation-native, а `live-probe` собирается
как отдельный executable для спайков без UI.

## 2026-11-15 — VoiceProcessingIO требует один клок
На встроенных микрофоне (48 кГц) и динамиках (44.1 кГц) `AVAudioEngine` по умолчанию
подключает `mainMixerNode → outputNode` на частоте выхода, а voice processing ждёт
общий клок. Отсюда `-10875` / `client-side input and output formats do not match`.
Подключаем mixer к output явно на частоте входа и берём каналы из
`outputNode.inputFormat`; при неудаче — освобождаем voice processing, ждём 400 мс
и поднимаем полудуплекс на новом engine. Полудуплекс — не «тихий режим»: во время
речи Gemini микрофон не отправляется, barge-in остаётся только в AEC-режиме.

## 2026-11-15 — live показывает HUD до suspend и стартует микрофон после setup
Ожидание подтверждения `suspend` от Python занимает до секунды; показывать HUD после
него — значит опаздывать с обратной связью на wake. Поэтому HUD презентуется сразу,
а микрофон поднимается только после `setupComplete`: иначе первые кадры уходят в
никуда (`sendAudio` ждёт setup), а смена аудиоконфигурации может помешать connect.
Плата — аудио, пришедшее от Gemini между setup и стартом микрофона, может потеряться
(миллисекунды); сид из wake отправляется уже после старта audio.

## 2026-11-15 — tap-замыкание живёт вне MainActor
`AVAudioEngine` вызывает tap на своём потоке. В Swift 6 замыкание, созданное в
`@MainActor`-методе, наследует изоляцию и падает с `dispatch_assert_queue_fail`.
Поэтому tap помечен `@Sendable`, конвертация выполняется в нём, а состояние и
колбэки обновляются через `Task { @MainActor ... }`.

## 2026-11-15 — mute мягкий: звук приложения не рвёт фразу
Раньше любой куй приложения вызывал `vad.reset()`: если звук попадал в середину
команды, уже сказанные слова терялись. Теперь `mute` по умолчанию идёт с
`keep_phrase: true` — кадры нашего звука заменяются тишиной, а VAD и текст реплики
живут дальше. Жёсткий сброс остался для `keep_phrase: false`; страховка
`MAX_MUTE_KEEP_SEC = 1 с` не даёт зависшему mute растянуть фразу навсегда.
Так как куй стал короче 300 мс, микрофон глушится на 0–0.33 с вместо 0.45 с.

## 2026-11-15 — куи синтезируются, а не берутся из системы
Системные `NSSound` (Funk, Glass, Basso) длятся 0.4–0.5 с и звучат громко, поэтому
требовали длинного mute и перекрывали речь. `SoundCueSynthesizer` строит куи
55–300 мс с пиком −15 dBFS, атакой 6 мс и релизом 30 мс (без щелчков); `SoundPlayer`
играет их через один `AVAudioEngine`-узел, и новый куй отменяет предыдущий.
Правила взяты из Alexa Design Guide: один звук — одно значение, куй короче 300 мс,
тише речи, не играет одновременно с её началом. Значения: `wake` — восходящая
терция, `sent` — короткий тик, `thinking` — тихая нота через 900 мс, `done` —
нисходящая терция, `error` — нисходящая малая терция, `stop` — низкий блип.

## 2026-11-15 — state на каждое изменение и быстрый стоп
`busy/speaking` уходили в Python только при старте и остановке озвучки, поэтому в
текстовом режиме `busy` оставался `false` и голое «стоп» игнорировалось. Теперь
`AppModel.apply(state:)` сравнивает флаги и шлёт `state` при каждой смене. Стоп-слово
распознаётся и на частичном тексте (не дожидаясь конца фразы), а «Гиро/Гира/Гэра/
Герания» добавлены в заполнители: раньше «Гиро, стоп» не считался стопом. Стоп-слово
больше не уходит событием `command` — Python сам эмитит `stop`, иначе Hermes начинал
выполнять «стоп» как промпт.

## 2026-11-15 — wake-куй молчит, если команда уже звучит
Если в событии `wake` уже есть inline-команда, пользователь ещё говорит: куй попал бы
в микрофон и оборвал её. В этом случае звук не играется, а подтверждение даёт короткий
`sent` в момент отправки команды. Панель при этом показывается всегда, даже если команда
придёт отдельным событием.

## 2026-11-15 — живой диалог завершается по прощанию, а не только по тишине
Ждать 60 секунд тишины после «спасибо» — это минута, когда микрофон и Gemini работают
впустую. Поэтому конец диалога определяется по смыслу на двух уровнях: модель вызывает
NON_BLOCKING-инструмент `finish_conversation`, а страховая связка `LiveEndMatcher` +
`LiveEndDetector` проверяет **всю** реплику пользователя на `turnComplete` (одно
«спасибо» — прощание, «спасибо, а теперь открой Safari» — нет). Закрытие мягкое: ждём
`turnComplete` и конец проигрывания, чтобы не оборвать прощальную фразу Гери;
предохранитель — 10 секунд. «Пока» и «до свидания» больше не считаются резкой
остановкой. После `finishLive` Python получает `resume` и снова слушает только
wake-слово; таймаут тишины остаётся последним резервом.

## 2026-11-16 — live забирает микрофон только после первой фразы
Раньше `startLiveDialog` сразу отправлял `suspend`, и Python закрывал микрофон в момент,
когда partial только распознал «Гера». Хвост фразы не слышал ни Whisper, ни Gemini.
Теперь `LiveConversation.prepare()` подключается к Gemini без микрофона, а `LiveStartup`
копит последнюю гипотезу каждой реплики и открывает шлагбаум на `utterance_end`.
Только после этого Swift забирает микрофон, запускает аудио Gemini и отправляет полный
текст первым ходом. Продолжения во время подключения Python ловит по `arm`; для
debug/URL-запуска без ушей есть `begin(skipWait:)`. Если live не поднялся, накопленный
текст уходит в обычный pipeline, поэтому команда не теряется. Первый ход приходит
в Gemini текстом, а не обрезанным аудио — это надёжнее и не зависит от момента,
когда открылся микрофон Gemini.

## 2026-11-16 — финальная фраза не теряет хвост без «Гера»
Корень потери был не в передаче микрофона, а в тексте: малая модель на следующей
гипотезе часто перестаёт писать «Гера», `WakeTracker.observe()` возвращал `False` и
оставлял первую короткую команду. А финальный текст большой модели без wake-слова
вообще игнорировался. Теперь после первого пробуждения любая следующая гипотеза
обновляет команду целиком (гипотеза из одного «Гера» её не стирает), а финальный
текст без призыва уходит событием `command` с `via: "final"` **до** `utterance_end`.
`best_command` не даёт короткому фрагменту заменить уже накопленную полную фразу.
`LiveStartup.note()` придерживается того же правила: гипотеза, которая является
началом или хвостом предыдущей, не затирает её. Так в Gemini первым ходом уходит
полная команда, даже если Whisper потерял wake-слово.

## 2026-11-16 — размер панели применяется вне прохода раскладки SwiftUI
Высота HUD приходит из `onGeometryChange`, то есть внутри layout/constraint pass.
Синхронный `panel.setFrame` оттуда запускает новый проход, поэтому
`PanelResizeScheduler` копит последнее значение и применяет его на следующем тике
main-очереди (`Task.yield()`), уже после раскладки; тот же планировщик использует
мини-окно ввода. Дополнительно `HUDHeardText` резервирует высоту двух строк (30 pt):
иначе typewriter-текст менял число строк на каждом partial. Само по себе это не
устранило краш: оставался второй владелец frame — SwiftUI (см. ниже).

## 2026-11-16 — SwiftUI-вью не должна быть contentView панели
`NSHostingView`, назначенный `contentView` окна, под SwiftUI App lifecycle на каждом
layout pass получает команду `updateAnimatedWindowSize` и сам ставит окну размер
корневой вьюхи. `sizingOptions = []` этот путь не выключает: SwiftUI проверяет
`window.contentView === hostingView`. Когда контроллер панели двигает frame сам,
два владельца запускают вложенные Update Constraints passes, и AppKit бросает
`NSGenericException`. Поэтому `FloatingPanel.host(_:)` кладёт hosting view внутрь
обычного `contentView` с autoresizing: у окна остаётся один владелец размера.
Рост HUD применяется прямым `setFrame`, без `animator()`. `reposition()` сравнивает
целевой frame с текущим и не трогает окно, если позиция уже верна: стрим вызывает
`show` на каждой дельте, и раньше это давало десятки лишних `setFrame` в секунду.

## 2026-11-17 — новые возможности строятся поверх инструментов Hermes
Gerania не дублирует поиск, браузер, управление компьютером, память и планировщик:
источник истины — toolsets Hermes (`web`, `browser`, `computer_use`, `memory`,
`cronjob`). Gerania добавляет UX: таймлайн действий, подтверждения, права, просмотр
памяти и планов. Своя логика остаётся только там, где Hermes не даёт нужного:
роутер бесплатных моделей между провайдерами, человеческие подписи инструментов
и аудит. `hermes fallback` не используется как основа роутера: он работает внутри
одного провайдера и не показывает пользователю переключение. Память читается из
`~/.hermes/memories/USER.md` и `MEMORY.md` (`§`-разделитель, лимиты 1375/2200),
планы — из `~/.hermes/cron/jobs.json` и `cron/output/`.

## 2026-11-17 — роутер моделей живёт в Gerania, а не в `hermes fallback`
`hermes fallback` работает внутри одного провайдера и не показывает пользователю
переключение. Gerania выбирает провайдера на каждый запрос сама: список кандидатов,
здоровье, кулдауны, реальная проверка. В ACP провайдер задаётся при запуске Hermes,
поэтому перебор работает в Авто/Gateway/One-shot; в настройках об этом честное
предупреждение.

## 2026-11-17 — формат кандидата `provider:model`
Делим по первому двоеточию, чтобы `openrouter:google/gemma-4-31b-it:free` и
`ollama:qwen3:8b` работали. Без префикса используется `settings.provider` — старые
списки моделей продолжают работать. Неизвестный префикс без слэша считается частью
модели, неизвестный префикс со слэшем — провайдером (`my-gateway:org/model`).

## 2026-11-17 — кулдауны вместо бесконечных повторов
После `quota` модель пропускается 10 минут, после `auth` — сутки, после `missing` —
30 минут. Здоровые модели идут первыми, остывающие — последними; если остывают все,
список всё равно пробуется целиком: устаревший кулдаун не должен оставить
пользователя без ответа. Кулдауны живут в памяти процесса — после перезапуска
пользователь мог поменять ключи.

## 2026-11-17 — возможности модели берём из кэша Hermes
`~/.hermes/models_dev_cache.json` читается только на чтение: оттуда бесплатность,
`tool_call`, vision и контекст. Своего каталога не держим. Незнакомая модель
считается рабочей с неизвестными возможностями, а не запрещённой. Ключи проверяются
только по именам переменных `.env`; значения не читаются и не логируются.

## 2026-11-17 — «Проверить» — это настоящий запрос, а не проверка ключа
`ModelProbe` запускает `hermes -z` с выбранными провайдером и моделью и ждёт ответ
до 45 с. Это единственный способ отличить «ключ есть» от «модель отвечает»:
ключ может быть просрочен, а модель — удалена. Сессия помечается `gerania-probe`,
чтобы тестовые ходы было видно в истории.

## 2026-11-17 — подписи инструментов и чипы в `thinking`
Сырые имена (`browser_exec`, `computer_use`) и аргументы превращаются в русские
фразы в `ToolDetail` + `ToolActivityFormatter`; HUD не показывает JSON. Чипы
действий видны уже в `.thinking` (последние три), а не только при прослушивании:
долгий tool-loop — это основное время ожидания, и пользователь должен видеть,
что Геря делает.

## 2026-11-17 — TCC-права принадлежат CuaDriver, а не Герании
`computer_use` выполняет клики и снятие экрана в отдельном подписанном приложении
`CuaDriver.app` (`com.trycua.driver`). macOS привязывает Accessibility и Screen
Recording к его identity, поэтому Герания не просит эти права у себя и не проверяет
их через `AXIsProcessTrusted`/`CGPreflightScreenCaptureAccess` — это был бы ответ про
саму Геранию. Статус читается из `hermes computer-use doctor --json`, а запрос прав
запускается через `hermes computer-use permissions grant`, чтобы диалог был привязан
к драйверу. Карточка в настройках ведёт в нужные панели System Settings.

## 2026-11-18 — результат инструмента приходит отдельным событием
`tool.complete` несёт и аргументы, и результат, и скриншот. Вместо расширения
`toolFinished` введено `toolOutput`, которое приходит перед ним: сигнатура
`toolFinished(id:ok:)` не меняется, а HUD и reducer могут сначала прикрепить
`image_path` и короткий итог, потом закрыть чип. Итог извлекает
`ToolResultSummary` в HermesKit, а не UI: это чистый разбор JSON, его удобно
тестировать без SwiftUI.

## 2026-11-18 — автостоп управления компьютером как напоминание
Полный автостоп после 10 минут мог бы оборвать полезную работу: человек отошёл,
а Гера как раз заканчивает длинную задачу. Поэтому по таймеру HUD показывает
янтарную полосу и озвучивает предупреждение, но ход продолжается; остановить
можно кнопкой «Остановить», голосом «стоп» или обычным прерыванием. Таймер
снимается, когда ни один `computer_use` больше не активен.

## 2026-11-18 — журнал действий пишется best-effort
`AuditLog` — отдельный actor с append-only JSONL: запись не блокирует UI и не
может уронить ход. Если диск полон или файл повреждён, ошибка уходит в лог,
а ответ пользователю продолжается. Аргументы маскируются до записи: токены,
пароли и `Authorization` заменяются на `***`, длинные строки обрезаются.
Журнал не является политикой безопасности — решения о подтверждениях
по-прежнему принимает Hermes.

## 2026-11-18 — память пишется в файлы напрямую, под общий lock
Gerania редактирует `~/.hermes/memories/USER.md` и `MEMORY.md` сама, а не через
`hermes memory` в терминале: нужен мгновенный отклик в окне настроек. Формат тот
же, что у `MemoryStore` Hermes (`\n§\n`, UTF-8), атомарная замена, права `0600`.
Захватывается тот же `USER.md.lock`/`MEMORY.md.lock`, что и у Hermes, поэтому два
писателя не пересекаются. Снимок при чтении содержит `MemoryFingerprint`
(mtime + размер + FNV-1a); при сохранении он сверяется — если файл изменили извне,
запись отклоняется и список перезагружается, а не затирает чужие записи.

## 2026-11-18 — знакомство формой, а не голосовым диалогом
Ответы знакомства превращаются в детерминированные записи `USER.md`, поэтому это
простая форма (имя, город, учёба, стек, стиль, заметка), а не голосовой диалог:
свободная модель может потерять поле между ходами, а форма пишет профиль одним
атомарным сохранением. Все поля необязательны, форму можно пропустить; часовой
пояс берётся из системы, а не спрашивается. Голосовой сценарий остаётся опцией
на будущее и не блокирует этап.

## 2026-11-18 — лимиты памяти берутся по умолчанию
`MemoryKind.limit` жёстко задаёт дефолты Hermes: `USER.md` — 1375, `MEMORY.md` —
2200 символов. Читать `memory_char_limit`/`user_char_limit` из
`~/.hermes/config.yaml` пока не стали: это ещё один парсер чужого конфига, а
дефолты совпадают с тем, что Hermes применяет без настроек. Если человек меняет
лимиты в конфиге, значения разойдутся — тогда добавим чтение и запись в
`DECISIONS.md`/`AGENTS.md`.

## 2026-11-18 — планы: файл читаем, меняем только через CLI
`jobs.json` принадлежит Hermes; Gerania его только парсит. Пауза, возобновление,
запуск, удаление и создание идут через `hermes cron ...`, потому что CLI держит
локи, проверяет cron-выражения и часовой пояс и сам пересчитывает `next_run_at`.
После каждого действия вкладка перечитывает файл, а не правит список локально:
так UI не расходится с планировщиком, даже если Hermes отказал или изменил поля.
Чтение — обычный файл, поэтому список работает без запуска процесса.

## 2026-11-18 — результаты планов показываем списком, без watcher (заменено ниже)
Вкладка берёт последние `cron/output/{job_id}/*.md` при открытии и по «Обновить»
и открывает файл через `NSWorkspace`. FSEvents, уведомления и HUD-карточку
отложили: они требуют разрешения на уведомления, интеграции с `AppModel` и
дедупликации прочитанного, а базовый сценарий «увидеть и открыть результат»
уже закрыт. Ошибки видны из `last_status`/`last_error`, без чтения
`executions.db`.

## 2026-11-18 — лимиты памяти читаются из config.yaml
Уточнение к решению «лимиты памяти берутся по умолчанию»: `MemoryLimits` всё-таки
читает `memory_char_limit`/`user_char_limit` из `~/.hermes/config.yaml`, потому
что человек может менять их в Hermes, и вкладка не должна показывать чужой
бюджет. Парсер намеренно терпимый (только секция `memory:`, целые числа,
комментарии игнорируются); при отсутствии файла или ключей остаются 1375/2200.

## 2026-11-18 — напоминания: Гера сама следит за `cron/output`
Заменяет решение «результаты планов показываем списком, без watcher». Причина:
для `--deliver local` Hermes только пишет `cron/output/<id>/<время>.md`
(`cron/scheduler_delivery.py`: для `local` целей доставки нет), поэтому
напоминание срабатывало молча. Теперь `CronMonitor` (в `GeraniaAppRoot`, живёт,
пока жив процесс) раз в 10 с читает папку и `cron/ticker_heartbeat`;
`CronResultTracker` (водяной знак по mtime + последние 100 id в `UserDefaults`)
объявляет каждый файл ровно один раз. Первый запуск — только точка отсчёта, без
лавины старых результатов. Опрос, а не FSEvents: один листинг дешёвый, не нужен
run-loop source, работает, пока `output/` ещё не создан. Результат = баннер
`UNUserNotificationCenter` (клик открывает файл) + HUD-карточка, если Гера не занята.
Задачи из чата (`cronjob` tool) попадают в ту же папку при любом `deliver`, поэтому
отдельная ветка для них не нужна.

## 2026-11-18 — напоминания при закрытом приложении
Выбрали «честно говорим, что нужна Гера в меню-баре», без заранее
запланированных локальных уведомлений. Тикает планировщик gateway Hermes
(`hermes gateway`, тик 60 с), он продолжает работать и без Геры, поэтому план всё
равно выполнится и файл появится. Пока Гера закрыта, уведомления нет. Пропущенные
результаты новее водяного знака и приходят при следующем запуске (до 3 баннеров +
сводка). Заранее планировать `UNNotificationRequest` не стали: текст напоминания —
ответ агента, его нет до запуска, а дубль «время пришло» без содержания путает.
Для «всегда вовремя» в окне советуем автозапуск при входе.

## 2026-11-18 — статус планировщика из heartbeat, а не из `hermes cron status`
`CronSchedulerStatus` читает `cron/ticker_heartbeat` (`<epoch> <pid>`) с тем же
порогом свежести, что у `hermes cron status` (3×60 с + 20 с). Это файл, а не процесс,
поэтому его можно опрашивать каждые 10 с. Кнопка «Запустить планировщик» вызывает
разрешённый `hermes gateway ensure --json --timeout 30` — тот же вызов, что делает
транспорт чата, второй gateway он не поднимет. Задачи, которые Hermes придержал,
видны по `last_fire_error.detail`, а просрочка больше 3 минут — по `next_run_at`.

## 2026-11-18 — мастер первого запуска: отдельное окно, все шаги можно пропустить
Выбор человека: отдельное мастер-окно, а не экран в главном окне. Оно открывается
вместо главного окна, пока не нажата «Готово» (флаг `onboardingCompleted` в
`UserDefaults`), и снова — из меню «Мастер настройки…». Закрыть окно крестиком значит
«позже»: мастер вернётся при следующем запуске. Любой шаг можно пропустить. Обязательны
только Hermes и модель: если они красные, внизу видно, что без них Гера не ответит.
Проверки (`SetupProbes`) только читают состояние. Исключение — проверка модели: это один
тестовый промпт `gerania-probe`, поэтому он идёт только на своём шаге, а не при открытии.
Визуально мастер продолжает экран загрузки и notch-HUD: чёрный фон, фиолетовый Геры,
стебель шагов, сегмент которого «дорастает», когда шаг готов (spring, без анимации
при reduce motion).

## 2026-11-18 — ключ модели живёт в Hermes, Гера его не пишет
Ключ провайдера Hermes хранится в `~/.hermes/.env`. Гера по-прежнему только сверяет
имена переменных (`ProviderCredentials`) и не пишет туда: менять конфигурацию Hermes
из Геры запрещено правилами проекта, а второе место хранения ключа приведёт к
расхождению. Шаг «Модель» ведёт в Hermes Desktop (`DesktopLauncher.openApplication`)
и проверяет модель тестовым промптом. Ключ Gemini Live — собственный ключ Геры, он
сохраняется в Связке ключей прямо в мастере и включает живой диалог, потому что Live
выбран основным режимом.

## 2026-11-18 — установка окружения голоса пока остаётся скриптом
Шаг «Микрофон и голос» честно показывает красный статус, если нет `voice-venv`, и
отсылает к README. Встроить установку в приложение (pip в фоне с прогрессом) — отдельная
задача среза 5: это сотни мегабайт моделей и ошибки сети, их нужно показывать отдельным
экраном, а не прятать в мастере.
