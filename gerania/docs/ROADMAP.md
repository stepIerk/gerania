# План: Гера как Siri для программистов и студентов

Дата: 2026-11-17. Статус: этап 1 закрыт; этап 2 закрыт (2.1, 2.2, 2.3 сделаны; живой сценарий — по желанию); этап 3 закрыт полностью (3.1, 3.2 текстовой формой, 3.3 чипом в HUD, предпросмотр и лимиты из `config.yaml`); этап 4 — 4.1 и шаблон 4.3 сделаны, 4.2 пока без watcher/уведомлений.

## Цель

Гера должна понимать голосовую команду, сама искать информацию, открывать браузер,
управлять компьютером, помнить пользователя и планировать его дела — и всё это
устойчиво работать на бесплатных моделях.

## Принципы

1. **Hermes — двигатель, Gerania — пульт.** Инструменты, память, cron и skills уже есть
   в Hermes. Gerania не дублирует их, а показывает, подтверждает и даёт управлять.
2. **Free-first.** Основной сценарий — бесплатные модели с честным переключением на
   запасные. Платные модели — опция, а не требование.
3. **Один вертикальный срез за раз.** Каждый этап заканчивается сценарием, который
   можно произнести голосом и увидеть в HUD.
4. **Опасное — через подтверждение.** Чтение и поиск можно автоматизировать; клики,
   ввод, терминал и удаление — только с явным согласием.
5. **Не ломать голос.** Любая новая функция обязана переживать «Гера → сразу речь»,
   barge-in, стоп-слова и закрытие HUD.

## Этап 1. Бесплатные модели: router (2–3 дня)

### 1.1 Кандидаты «провайдер:модель»

Сейчас `settings.modelCandidates` — список голых id, а провайдер один на всё приложение.
Для бесплатных моделей это не работает: Gemini, OpenRouter и локальный Ollama — разные
провайдеры.

- Новый тип `ModelCandidate { provider, model, id }` в `GeraniaCore`.
- Формат строки: `provider:model`. Делим по **первому** двоеточию, чтобы не ломать
  `openrouter:google/gemma-4-31b-it:free` и `ollama:qwen3:8b`.
- Без префикса — текущий `settings.provider` (обратная совместимость со старыми настройками).
- `makeTransport(model:provider:)`; кэш транспорта сравнивает пару, а не только модель.
- `hermes fallback` не используем как основу: он живёт внутри одного провайдера и не
  показывает пользователю, что произошло. Наш router — источник истины.

### 1.2 Готовые пресеты (проверены по `models.dev` и Hermes)

| Gemini Flash | `gemini:gemini-2.5-flash` | да, лучше | Запасной на сложные задачи |

### 1.3 Проверка возможностей и доступности

- `models_dev_cache.json` (6.6 МБ, `~/.hermes/models_dev_cache.json`) даёт `tool_call`,
  `limit.context` и `cost`. Читать лениво, кэшировать по mtime.
- Бейджи в настройках: **бесплатная**, **инструменты**, **vision**, **контекст**.
- Если у модели `tool_call = false` — предупреждение: «Не сможет открыть браузер и
  управлять компьютером». Это критично для free-моделей.
- Доступность провайдера: имена ключей в `~/.hermes/.env` (только имена, значения не
  логировать) + OAuth-провайдеры из `~/.hermes/auth.json` + `provider_models_cache.json`.
  Ключ не нужен для `custom`/`ollama`/`lmstudio`.
- Кнопка «Проверить»: один короткий one-shot (`hermes -m … --provider … -z "ответь OK"`)
  с таймаутом 20 с. Результат кэшировать на час.

### 1.4 Алгоритм переключения

1. Собрать кандидатов в порядке пользователя.
2. Пропустить тех, у кого нет ключа/сервера.
3. Пропустить «остывающих»: 429/quota — 10 минут, model not found — 24 часа,
   auth error — до изменения настроек.
4. Идти по списку; при `HermesError.isModelUnavailable` помечать и брать следующего.
5. При переходе внутри одного хода: короткая подпись в HUD «Запасная модель: …» и,
   если включена озвучка, фраза «Модель занята, беру запасную». Не озвучивать при
   обычном старте.
6. Если кончились все — человеческое сообщение со списком проверенных моделей и
   кнопкой «Открыть настройки моделей».

- «Добавить вручную» — поле `provider:model`.
- «Проверить все» — последовательная проверка с прогрессом.
- Переключатель «Показывать модель в HUD» (по умолчанию выключен, чтобы не шуметь).

### Файлы

- `GeraniaCore/ModelCandidate.swift` (новый), `GeraSettings.swift` — хранить строки,
  парсить в кандидатов.
- `HermesKit/ModelCapabilities.swift` (новый) — чтение `models_dev_cache.json`.
- `GeraniaUI/AppModel+Turn.swift` — цикл по кандидатам с провайдером, `ModelHealthStore`.
- `GeraniaUI/Settings/ModelCandidatesSection.swift` — переписать под карточки.

### Готово когда

- Старый список без префиксов продолжает работать.
- При искусственном 429 на Gemini Геря сама отвечает через OpenRouter и говорит об этом.
- Модель без `tool_call` помечена, и Геря предупреждает, что браузер/компьютер недоступны.
- Unit-тесты: парсер `provider:model`, порядок кандидатов, cooldown, «нет ключа».

## Этап 2. Компьютер и интернет (3–4 дня)

### 2.1 Человеческий таймлайн действий

Сейчас HUD показывает `tool.start.context` — обычно пустую или техническую строку.
В gateway-событии уже есть `args` и `result`, их нужно использовать.

- Расширить `HermesEvent.toolStarted` аргументами (или ввести `ToolActivity` в `GeraniaCore`).
- `ToolActionFormatter` — таблица «инструмент + args → русская подпись + SF Symbol»:
  - `web_search` → «Ищу: {query}»
  - `web_extract` → «Читаю страницу: {host}»
  - `browser_exec` → «Браузер: {первая осмысленная строка}»
  - `computer_use` → по `action`: «Смотрю экран», «Кликаю: {app}», «Печатаю», «Нажимаю {key}»
  - `terminal` → «Команда: {command}»
  - `read_file` / `write_file` / `patch` → «Читаю / пишу: {path}»
  - `memory` → «Запоминаю», `cronjob_manage` → «План: {action}»
  - `vision_analyze` → «Смотрю изображение», `delegate_task` → «Подзадача: {цель}»
- HUD: одна строка текущего действия + счётчик «+N»; полный список — в окне ответа.
- Из `tool.complete` брать `image_path` и показывать миниатюру скриншота в окне ответа.
- Из `result` брать короткий итог (URL, заголовок, число результатов), не весь JSON.

Сделано: `HermesEvent.toolOutput` + `GeraAction.toolOutput`, поля `ToolChip.imagePath`
и `ToolChip.summary`, `ToolResultSummary` (число результатов/страниц, заголовок,
код выхода, ошибка), счётчик «+N» в HUD и таймлайн `ToolTimelineView` с миниатюрой

### 2.2 Права и онбординг

`computer_use` работает через cua-driver, ему нужны Accessibility и запись экрана.
Gerania должна объяснить это человеку, а не падать.

- `PermissionsStatus` в `HermesKit`: Accessibility (`AXIsProcessTrusted`), Screen
  Recording (`CGPreflightScreenCaptureAccess`), плюс статус cua-driver.
- Карточка в настройках: зелёная/жёлтая/красная, кнопка «Открыть системные настройки»
  (`x-apple.systempreferences:…Privacy_Accessibility` и `…Privacy_ScreenCapture`).
- При первой команде управления: короткая подсказка в HUD, что нужно разрешение,
  и кнопка «Проверить снова» — без бесконечных диалогов.
- Выяснено: TCC-разрешения принадлежат `CuaDriver.app` (`com.trycua.driver`), а не
  Герании и не hermes. Статус читается из `hermes computer-use doctor --json`;
  шаги записаны в `HUMAN_TODO.md`, карточка «Компьютер» уже в настройках.

### 2.3 Безопасность действий

### 3.1 Вкладка «Память»

- Две колонки: «О пользователе» и «Заметки Геры».
- Каждая запись — карточка с кнопками «Изменить» / «Забыть».
- Счётчик символов с лимитом; при переполнении — предупреждение.
- «Добавить факт» — свободный текст.
- «Забыть всё» — `hermes memory reset` с двойным подтверждением.
- Прямая запись в файлы: атомарная замена + собственный lock-файл, отказ при
  изменении файла извне (сравнение mtime и хэша). Формат записи — как у
  `MemoryStore`: `\n§\n`.

### 3.2 Знакомство при первом запуске

Опциональный голосовой сценарий (можно пропустить):

- имя и как обращаться;
- город и часовой пояс;
- учёба/работа: дни, время, типичные дедлайны;
- стек: языки, редактор, что изучает;
- стиль ответов: коротко/подробно, с примерами кода или без.

Ответы превращаются в 5–8 записей `USER.md`. Дальше Геря использует их в брифинге
и в обычных ответах — без отдельного кода, через системный промпт Hermes.

### 3.3 Что показать в HUD

## Порядок и оценка

| Этап | Что даёт | Оценка |
|---|---|---|
| 1. Router | Переживает лимиты бесплатных моделей, понятный выбор модели | 2–3 дня |
| 2. Компьютер и интернет | Главная «вау»-функция: Геря реально действует | 3–4 дня |
| 3. Память | «Кто я, что люблю, когда пары» | 2–3 дня |
| 4. Планы | Напоминания, брифинг, недельный обзор | 2–3 дня |
| 5. Сценарии | Удобство для кода и учёбы | 3–4 дня |

Разумный первый срез: **1 + подписи действий из 2.1** — бесплатные модели перестают
быть хрупкими, а HUD сразу показывает, что Геря делает.

## Проверочные сценарии (E2E)

1. «Гера, найди, когда дедлайн по матанализу» → поиск → короткий ответ голосом.
2. «Гера, открой ютуб и найди видео про SwiftUI» → браузер → подтверждение → ответ.
3. «Гера, запомни, что пары по средам в 10:00» → запись в памяти → знание в новой сессии.
4. «Гера, напоминай каждый день в 8 утра про план» → задача → уведомление утром.
5. «Гера, что у меня сегодня» → брифинг из памяти, календаря и напоминаний.
6. «Гера, стоп» в любой момент → действие прервано, HUD не падает.

## Риски и как их снимаем

- **Слабые free-модели ломают tool-loop.** Фильтр `tool_call`, пресеты с проверенными
  моделями, cooldown, переключение на Gemini Flash при ошибке.
- **Лимиты free tier.** Router с несколькими провайдерами и честное сообщение, когда
  всё закончилось; кнопка «добавить запасную».
- **Права TCC у cua-driver.** Выяснить точное приложение до реализации и записать шаги
  в `HUMAN_TODO.md`; без прав — понятная карточка, а не зависание.
- **Автоматизация чужих сайтов хрупкая.** Браузер — для обычного веба; для API-сервисов
  используем ключи и навыки, а не клики по чужому UI.
- **Память меняется только со следующей сессии.** Написать это в UI и предлагать
  «Начать новый чат», когда пользователь правит профиль.
- **Утечка ключей в логи.** Читать только имена переменных `.env`, значения не логировать.

2. Какие бесплатные провайдеры подключаем первыми: OpenRouter (нужен ключ),

3. Нужен ли платный fallback или строго бесплатные модели.
4. Разрешать ли в текстовом режиме авто-подтверждение чтения (поиск, скриншоты)
   или спрашивать всегда.
