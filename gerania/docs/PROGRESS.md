## 2026-11-16 — HUD: настоящая причина падения — SwiftUI владел frame панели

Проблема:
- После «Гера» HUD падал с `NSGenericException: The window has been marked as
  needing another Update Constraints in Window pass...`.
- Первый фикс (отложенный `panel.setFrame` + зарезервированная высота
  `HUDHeardText`) не помог: пользователь воспроизвёл краш повторно.
- Настоящая причина: `PanelHost` (`NSHostingView`) был назначен
  `contentView` панели. Под SwiftUI App lifecycle SwiftUI на каждом проходе
  раскладки вызывает `updateAnimatedWindowSize` и ставит окну размер корневой
  вьюхи; `sizingOptions = []` на это не влияет (гейт — `window.contentView ===
  hostingView`). Контроллер одновременно двигал frame сам. Два владельца одного
  frame запускали вложенные Update Constraints passes, и AppKit после лимита
  бросал исключение.
- Дополнительно каждый `.textDelta` возвращал эффект `.showPanel`, а
  `HUDPanelController.show` вызывал `reposition()` даже для уже видимой панели:
  до 30 лишних `setFrame` в секунду во время стрима.

Сделано:
- `FloatingPanel.host(_:)` добавляет `NSHostingView` **под** `contentView`
  (обычный `NSView`), включает autoresizing по ширине и высоте. SwiftUI больше
  не является владельцем размера окна. Через этот метод теперь создаются HUD,
  мини-окно ввода и окно полного ответа.
- `HUDPanelController.reposition` не двигает окно, если frame уже совпадает:
  раньше каждый `.textDelta` вызывал `show → reposition → setFrame` (до 30 лишних
  переносов в секунду), теперь это no-op.
- Рост HUD применяется прямым `panel.setFrame` без `animator()`: анимация окна
  во время раскладки SwiftUI добавляла второй ритм изменения размера.
  `PanelResizeScheduler` остаётся вторым рубежом и по-прежнему откладывает
  изменение высоты наружу из прохода раскладки.
- `HUDHeardText` сохраняет резерв двух строк (30 pt) и печать с уже видимого
  префикса.
- Debug-состояние `gerania://debug/state?name=heard` показывает «Слушаю» с длинной
  распознанной фразой; smoke снимает `heard.png`.
- Тест `FloatingPanelHostTests`: hosting view не является `contentView`, лежит
  внутри него и растягивается вместе с панелью.

Проверено:
